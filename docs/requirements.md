# 책 참여 비용 실험 웹 애플리케이션 요구사항

## 1. 범위와 적용 기준

- 근거는 [기존 실험 계획](experiment.md)과 사용자가 확정한 변경사항이다.
- 기존 목적·핵심 가설·주 성공 기준은 유지한다. 진입·공개·게시물·수집 정책은 최신 확정사항을 따른다.
- 기존 계획과 UX가 달라진 부분은 본 문서가 우선한다. experiment.md는 수정하지 않는다.
- 실제 서비스 완성이 아닌 최소 실험 앱을 정의한다. 이 문서는 구현 코드가 아니며 이번 작업은 requirements.md만 수정한다.
- 미확정 사항은 17절에 모은다. 확정 정책을 임의 확장하지 않는다.

## 2. 프로젝트 목적

책의 특정 장면과 이모지·투표·한 줄 감상이라는 낮은 비용의 참여 수단을 제공했을 때 사용자 표현 비율을 측정한다. 이후 타인 감상 소비, 좋아요·답글, 자유 감상으로 이어지는 행동을 수집한다.

산출물은 세 도서의 동일 구조 실험 화면, 익명 행동을 연결하는 SQLite 데이터, 전체·도서별 지표와 CSV다. 완성된 독서 커뮤니티 구축을 목적으로 하지 않는다.

## 3. 가설·표본·성공 기준

### 3.1 가설

책 전체의 자유 형식 감상을 바로 요구하는 것보다, 특정 장면과 이모지·투표·한 줄 감상을 제공하면 더 많은 사용자가 책에 대한 생각을 표현한다.

### 3.2 표본과 주 성공 기준

- 고유 방문자는 실험 기간 중 실제 도서 페이지에서 book_view가 발생한 서로 다른 visitor_id다.
- landing_view 또는 book_select만 있는 사용자는 주 분모에 포함하지 않는다.
- 전체 목표·최소 표본은 **고유 도서 방문자 50명**이다. 도서별 50명을 요구하지 않는다.
- 50명 도달은 최소 표본 충족이며 자동 종료 조건이 아니다. 운영자가 직접 종료하고 종료 시각을 확정한다. 종료 시각은 환경 설정 등 최소 운영 수단으로 기록하며 별도 운영 CMS는 추가하지 않는다.
- is_test로 표시된 개발 테스트 visitor는 표본·참여율 등 모든 실험 집계에서 제외한다. 관리자 접근 자체는 visitor를 테스트로 전환하지 않는다. 테스트 제외 후의 전체 고유 방문자 수로 50명 충족 여부를 판단한다.
- 전체는 세 도서 방문자 집합의 합집합이다. 같은 visitor가 세 도서를 방문해도 1명이다.
- 도서별 표본·참여율은 탐색 지표로 제공한다.

| 조건 | 분자 / 분모 | 기준 |
| --- | --- | --- |
| 가벼운 참여율 | 이모지 또는 투표 성공 참여 고유 사용자 / 고유 도서 방문자 | 30% 이상 |
| 텍스트 참여율 | 한 줄 최초 제출 성공 고유 사용자 / 고유 도서 방문자 | 10% 이상 |

두 조건을 모두 충족해야 한다. 이모지·투표 중복 참여자는 합집합에서 한 번만 센다. 작성 시작은 제출이 아니다. 변경·취소·수정·삭제 후에도 기간 중 성공 참여 사실을 유지한다. 판정에는 반올림 전 비율을 사용한다.

### 3.3 판정

| 조건 | 최종 판정 |
| --- | --- |
| 전체 방문자 50명 미만 | 판정 불가 |
| 50명 이상·데이터 신뢰 가능·주 기준 둘 다 충족 | 검증 |
| 50명 이상·데이터 신뢰 가능·하나 이상 미충족 | 기각 |
| 데이터 오염 등 신뢰 불가 | 표본·비율과 무관하게 판정 불가 |

분모 0은 N/A다. 관리자에서 표본 충족, 각 비율·기준 충족, 두 조건 동시 충족, 최종 판정을 구분한다. 자유 감상·상호작용은 탐색 지표이며 주 판정을 바꾸지 않는다.

**해석 제한:** 대조군이 없으므로 이 결과만으로 참여 비용 감소가 참여율 증가의 인과적 원인이라고 확정하지 않는다. 이전 실험 비교 시 모집·기간·분모의 비교 가능성을 확인한다. 대조군·A/B 기능은 추가하지 않는다.

## 4. 대상 도서와 콘텐츠

《변신》, 《노인과 바다》, 《어린 왕자》를 사용한다. 기존 선정 순위·비율은 선정 근거이며 앱에서 실시간 갱신하지 않는다.

### 4.1 《변신》

- 장면: 생계를 책임지던 그레고르가 벌레로 변한 뒤 가족과의 관계가 달라지는 부분.
- 상황 설명: “어느 날 아침, 그레고르는 거대한 벌레로 변해버립니다. 그전까지 그는 가족의 빚을 갚기 위해 매일 일하며 가족의 생계를 책임지고 있었습니다. 하지만 벌레가 된 뒤 더 이상 일을 할 수 없게 되고, 시간이 흐르면서 가족의 태도도 달라지기 시작합니다.”
- 원문 발췌: 확정 전 슬롯 유지.
- 이모지 질문: “이 장면을 읽고 가장 먼저 든 감정은 무엇인가요?”
- 선택지: 😢 슬프다 / 😡 화난다 / 😨 무섭다 / 🤔 생각이 많아진다 / 😶 잘 모르겠다.
- 투표 질문: “가족의 태도 변화를 이해할 수 있나요?”
- 설명: “그레고르는 가족을 위해 일했지만, 이제는 아무런 경제적인 도움도 줄 수 없는 상태입니다.”
- 선택지: 어느 정도 이해할 수 있다 / 이해하기 어렵다 / 잘 모르겠다.
- 한 줄 질문: “그레고르의 상황에서 가장 씁쓸하게 느껴지는 점은 무엇인가요?”
- 보조 문구: “한 문장이면 충분해요.”

### 4.2 《노인과 바다》

- 장면: 산티아고가 청새치를 잡은 뒤 돌아오는 길에 상어들에게 빼앗기는 부분.
- 상황 설명: “늙은 어부 산티아고는 84일 동안 물고기를 한 마리도 잡지 못했습니다. 그리고 85일째 되는 날, 혼자 먼 바다로 나가 거대한 청새치와 며칠에 걸쳐 사투를 벌입니다. 마침내 청새치를 잡는 데 성공하지만, 돌아오는 길에 상어들이 나타납니다.”
- 원문 발췌: 확정 전 슬롯 유지.
- 이모지 질문: “산티아고의 마지막 모습을 보고 어떤 감정이 들었나요?”
- 선택지: 🫡 존경스럽다 / 😢 허무하다 / 🔥 대단하다 / 🤔 생각이 많아진다 / 😶 잘 모르겠다.
- 투표 질문: “산티아고의 도전은 실패였을까요?”
- 설명: “그는 결국 거대한 청새치를 잡았지만, 마을로 돌아왔을 때 남은 것은 뼈뿐이었습니다.”
- 선택지: 실패라고 생각한다 / 실패가 아니라고 생각한다 / 잘 모르겠다.
- 한 줄 질문: “결과가 남지 않은 노력에도 의미가 있다고 생각하나요?”
- 보조 문구: “당신의 생각을 한 문장으로 남겨주세요.”

### 4.3 《어린 왕자》

- 장면: 여우와 어린 왕자가 관계를 맺고 함께한 시간이 서로를 특별하게 만드는 부분.
- 상황 설명: “여행을 하던 어린 왕자는 지구에서 여우를 만납니다. 여우는 어린 왕자에게 자신과 관계를 맺어달라고 부탁합니다. 처음에는 서로에게 수많은 사람과 여우 중 하나일 뿐이지만, 함께 시간을 보내면서 서로에게 특별한 존재가 됩니다.”
- 원문 발췌: 확정 전 슬롯 유지.
- 이모지 질문: “어린 왕자와 여우의 이야기를 읽고 어떤 감정이 들었나요?”
- 선택지: ❤️ 따뜻하다 / 🥹 뭉클하다 / 😢 슬프다 / 🤔 생각이 많아진다 / 😶 잘 모르겠다.
- 투표 질문: “함께한 시간이 길수록 그 사람은 나에게 더 특별해진다고 생각하나요?”
- 선택지: 그렇다 / 꼭 그렇지는 않다 / 잘 모르겠다.
- 한 줄 질문: “당신에게 누군가와 '관계를 맺는다'는 것은 어떤 의미인가요?”
- 보조 문구: “한 문장으로 표현해주세요.”

### 4.4 공통 콘텐츠 정책

- 짧은 상황 설명과 **실제 작품 원문 발췌 텍스트**를 함께 제공한다. 요약문만으로 대체하지 않는다.
- 발췌는 텍스트 데이터로 직접 입력하여 표시한다. 이미지·책 페이지 사진을 사용하지 않는다.
- 실험 전 실제 원문, 출처, 사용 번역본, 사용 가능 여부, 콘텐츠 버전을 확정한다. 원작·번역 저작권 문제가 있는 텍스트를 임의로 가져오지 않는다.
- 미확정 시 슬롯만 유지한다. Codex가 원문을 생성하거나 외부에서 가져오지 않는다. 슬롯을 확정 원문처럼 표시하거나 원문 없이 실제 실험을 시작하지 않는다.
- 세 도서의 구조는 동일하며 이모지 5개·투표 3개다.
- 모든 한 줄 placeholder는 “떠오른 생각을 한 문장으로 적어주세요.”다.
- 콘텐츠는 고정 데이터로 관리한다. 실험 중 변경은 버전·적용 시각을 기록하여 분석에서 구분한다. 편집 CMS는 만들지 않는다.
- 예시 통계·감상을 실제 결과처럼 넣지 않는다.

## 5. 전체 플로우와 랜딩

랜딩 `/` → 책 선택 → 상황 설명 → 원문 발췌 → 이모지 → 투표 → 한 줄 감상 → “다른 사람들의 감상 보기” → 커뮤니티 → 좋아요·답글 → 선택적 자유 감상.

- 이모지·투표·한 줄은 모두 선택 사항이다. 표시 순서는 필수 진행 순서가 아니다. 전혀 참여하지 않고 커뮤니티로 넘어갈 수 있다.
- 별도의 `[내 생각 남기기 완료]` 버튼은 없다.
- 한 권만 참여하고 종료하거나 원하는 두 권·세 권에 참여할 수 있다.
- `/`에서 세 도서를 자유롭게 선택한다. 최초 방문에 도서 순서를 무작위 배정한다.
- 가능한 한 visitor_id에 순서를 보관하여 재방문에 유지한다. 유지 불가·ID 변경으로 재배정할 수 있으나 매 landing_view에 실제 순서를 남긴다.
- display_position은 해당 랜딩 표시 순서 1·2·3이다. PC·모바일에서도 같은 의미다.
- `1/3 완료`, `2권 남았습니다`, `모든 책에 참여해보세요`, 진행률, 완료 보상을 제공하지 않는다.
- 랜딩 표시·선택·실제 도서 방문은 별도 행동이다. 도서 직접 방문도 book_view로 기록하되 book_select를 가짜로 만들지 않는다.
- 같은 visitor_id가 해당 도서 커뮤니티를 한 번 직접 열었다면 재방문에서 자동 복원한다. 복원은 community_open을 만들지 않으며 실제 타인 감상 50% 노출 시 others_reveal을 새 페이지에서 기록한다.

## 6. 화면별 기능과 공개 조건

### 6.1 구성과 독립 공개

| 화면·영역 | 내용 | 공개 조건 |
| --- | --- | --- |
| 랜딩 `/` | 무작위 순서의 세 도서 선택 | 익명 접근 |
| 개별 반응 | 상황 설명·원문·이모지·투표·한 줄 입력 | 익명 접근, 모두 선택 사항 |
| 이모지 결과 | 현재 유효 선택 분포 | 해당 도서 이모지 저장 성공 |
| 투표 결과 | 현재 유효 투표 수·비율 | 해당 도서 투표 저장 성공 |
| 개별 한 줄 영역의 타인 글 | 타인의 한 줄 감상 | 자신의 한 줄 최초 제출 성공 또는 커뮤니티 진입 |
| 커뮤니티 | 자신의 글을 포함한 한 줄·자유 감상, 좋아요 수, 답글·답글 수, 자유 작성 CTA | 최초 CTA 선택·공개 또는 같은 visitor·도서의 이전 직접 공개 이력으로 자동 복원 |
| 관리자 | 지표·판정·CSV | 관리자 인증 |

감상 목록은 자신의 글도 타인 글과 같은 목록에 표시하며 `내 감상` 표식을 붙인다. 목록에 자신의 글이 있다는 사실은 타인 감상 노출 조건이 아니다.

“하나 참여하면 모든 결과 공개” 모델은 사용하지 않는다. 각 상태는 같은 visitor_id·book_id에서 독립 판정한다. A 도서 참여는 B 도서 결과를 공개하지 않는다. 숨겨진 개별 결과는 서버 응답에서도 제한하며 CSS로만 숨기지 않는다.

이모지·투표 결과와 개별 타인 한 줄은 각각 최초 성공으로 획득한 공개 자격을 유지한다. 반응 취소·한 줄 삭제 후에도 다시 숨기지 않으며 재방문에도 복원한다. 공개 자격은 현재 활성 선택·본문 유무가 아니라 서버의 성공 이력으로 판정한다.

성공·실패를 구분한다. 저장 실패를 성공으로 표시하거나 해당 반응 결과를 먼저 공개하지 않는다. 오류 시 입력을 유지하고 동일 요청을 재시도할 수 있어야 한다. 데이터 없음은 빈 상태로 표시한다.

### 6.2 이모지·투표

- 각각 사용자·도서당 현재 하나만 유지한다. 선택 즉시 저장하고 성공 후 자신의 선택과 해당 종류 결과만 공개한다.
- 이모지는 투표·타인 한 줄을, 투표는 이모지·타인 한 줄을 공개하지 않는다.
- 각각 변경·취소 가능하다. 변경은 기존 선택을 대체하고 취소는 현재 유효 선택을 제거한다.
- 같은 선택 재클릭·재요청은 새 상태·성공 이벤트가 아니다.
- 분포는 현재 유효 선택 기준이다. 투표 비율의 분모는 유효 투표 수이며 방문자·이벤트 수가 아니다. 0표는 N/A다.
- 변경·취소·재선택 이력은 기록한다. 고유 참여는 기간 중 선택 성공 기준이며 이후 취소해도 소급 제거하지 않는다. 취소만으로 새 참여자를 만들지 않는다.
- 취소 후에도 이미 공개된 해당 결과를 계속 공개하고 재방문에도 복원한다. 현재 유효 선택이 없어도 과거 성공 이력으로 공개 가능하다.

### 6.3 한 줄 감상

- 사용자·도서당 최대 1개, 최대 150자다. 공통 placeholder는 “떠오른 생각을 한 문장으로 적어주세요.”다.
- 최소 분량은 요구하지 않으며 공백만 있는 글은 거부한다.
- 최초 제출·수정·삭제·삭제 후 재작성을 허용하고 구분한다. 재작성은 같은 글 재활성화이며 여러 한 줄을 생성할 수 없다.
- short_review_submit은 최초 제출 성공만 뜻한다. 수정·삭제는 short_review_update/short_review_delete다.
- 삭제 후에도 최초 제출 이벤트·시각·대상을 보존하며 과거 참여자를 제거하지 않는다.
- 한 줄 삭제 후에도 이미 공개된 타인의 한 줄을 계속 공개한다. 재작성은 같은 review_id의 short_review_update(action=restore)이며 최초 short_review_submit을 다시 만들지 않는다.
- 개별 영역에서는 제출 전 타인의 한 줄을 먼저 보여주지 않는다. 제출 성공 시 타인의 한 줄만 공개한다.
- 미제출자도 CTA로 커뮤니티에 들어가면 타인의 한 줄을 볼 수 있다. 한 줄 제출은 이모지·투표 결과를 공개하지 않는다.

### 6.4 커뮤니티와 조회

- 개별 반응 다음에 “다른 사람들의 감상 보기” CTA를 제공한다. 참여 여부와 무관하게 선택 가능하다.
- 선택으로 실제 공개되면 community_open을 기록한다. CTA 노출·실패 클릭만으로 기록하지 않는다.
- 같은 visitor·도서에서 이전 community_open 성공 이력이 있으면 커뮤니티를 자동 복원한다. 새 community_open은 만들지 않으며 서버에서도 과거 직접 공개 이력으로 접근을 허용한다.
- 한 줄·자유 감상, 각 좋아요 수, 답글·답글 수, 자유 작성 CTA를 모두 제공한다. 자신의 글도 타인 글과 같은 목록에 표시하고 `내 감상`으로 구분한다. 자신의 글을 타인 노출로 집계하지 않는다.
- 커뮤니티 조회·상호작용·자유 감상 요청은 서버에서도 해당 도서의 커뮤니티 공개 상태를 확인한다. 반응 제출 이력을 접근 조건으로 요구하지 않는다.
- 커뮤니티 공개는 미참여 이모지·투표 결과를 공개하지 않는다.
- 한 줄·자유 감상은 각각 최신순으로 표시한다. 같은 시각에는 안정적인 ID 순서로 구분한다. 수정으로 최초 작성 순서를 바꾸지 않는다.
- 삭제 후 재작성도 기존 글의 최초 제출 시각을 유지한다. 답글은 오래된 순으로 표시하며 수정으로 순서를 바꾸지 않는다.
- 소규모 표본 전제로 해당 도서 감상을 한 번에 조회한다. 페이지네이션·무한 스크롤·인기순·추천은 없다.
- 삭제된 글·답글은 공개 목록·본문·현재 수에서 제외하되 과거 행동을 보존한다.
- 목록 노출은 모든 글을 읽었음을 뜻하지 않는다.
- others_reveal은 직접 CTA 진입·자동 복원·개별 한 줄 공개 등 경로와 무관하게 실제 타인 감상 영역의 50% 이상 노출을 측정한다. 빈 목록이나 자신의 글만 보이는 영역으로 타인 감상 노출을 생성하지 않는다.

### 6.5 좋아요·답글

- 커뮤니티에서 자신의 감상 작성 여부와 관계없이 타인 글에 좋아요·답글 가능하다.
- 좋아요 취소 가능, 동일 visitor·감상에 현재 유효 좋아요는 최대 1개다. 취소·재좋아요로 고유 참여자를 늘리지 않는다.
- 답글은 최대 300자, 여러 개 작성·수정·삭제 가능, 공백만 입력 불가다.
- 대상은 한 줄·자유 감상이며 1단계만 지원한다. 중첩 답글은 없다.
- 본인 감상 좋아요·답글은 제공하지 않으며 지표에서도 제외한다. 다른 도서·삭제된 감상에 새 상호작용을 허용하지 않는다.
- 작성창 열기와 최초 등록 성공을 분리한다. 수정은 제출로 다시 세지 않는다.

### 6.6 자유 감상

- 사용자·도서당 최대 1개, 최대 2,000자, 최소 분량 없음, 공백만 입력 불가다.
- 작성·수정·삭제·삭제 후 재작성 가능하며 최초 제출 이력은 유지한다. 재작성은 같은 review_id의 full_review_update(action=restore)이며 최초 full_review_submit을 다시 만들지 않는다.
- 커뮤니티에서 “조금 더 이야기하고 싶나요?”와 “앞에서 남긴 생각이나 다른 사람의 의견을 보고 떠오른 생각을 자유롭게 남겨주세요.”를 표시한다. 버튼은 “더 이야기하기”다.
- 선택 시 입력창과 “등록하기”를 제공한다.
- 자신의 한 줄·자유 감상을 먼저 쓰지 않아도 타인의 자유 감상을 읽고 상호작용할 수 있다.

### 6.7 글 정책 공통 기준

- 서버가 길이·공백 여부를 검증하고 클라이언트도 같은 기준을 안내한다. 상한은 본문 전체 Unicode 코드 포인트 수이며 내부 공백·줄바꿈을 포함한다.
- 해당 visitor_id의 글만 수정·삭제 가능하다. 서버에서 소유자를 검사한다.
- 삭제는 공개 글을 제거하되 ID·최초 제출·삭제 시각·이벤트 연결을 유지하는 논리 삭제다. 실험 중 삭제 본문은 비공개로 보관한다.
- 한 줄·자유 감상 재작성은 기존 사용자·도서·종류의 review_id를 다시 활성화하여 본문을 저장한다. 새 행을 만들지 않고 deleted_at을 해제하며 최초 제출 시각·이벤트를 보존한다. update 이벤트의 action=restore로 일반 수정(action=edit)과 구분한다.
- 실험 종료 후 논리 삭제 상태의 본문을 폐기할 수 있게 한다. 운영자가 확정한 보관 기간·폐기 시점에 본문을 제거하고 body_purged_at을 남기되 사용자·도서·글 ID·최초 제출·이벤트 연결은 유지한다. 재활성화된 유효 글의 본문은 삭제 상태 본문 폐기 대상으로 취급하지 않는다.
- 본문 폐기는 공개 감상 삭제와 다른 운영 처리이며 추가 submit/delete 참여 이벤트를 만들지 않는다. 폐기 이후 CSV에서도 폐기 상태와 시각을 표시하고 삭제 본문을 복원하지 않는다. 폐기 적용 범위는 관련 Export·백업 사본까지 보관 정책에서 확정한다.

## 7. 익명 식별·관리자 접근

### 7.1 익명 visitor

- 서버 발급 UUID visitor_id를 영속 쿠키에 저장한다. 기본 수명 30일이다.
- 같은 브라우저 새로고침·재방문·다중 탭에서 유지한다. 식별 확정 전에 행동을 기록해 ID가 분산되지 않도록 한다.
- 요청의 UUID 형식·발급 여부를 확인한다. 운영 HTTPS에서 Secure·HttpOnly·적절한 SameSite를 적용한다.
- 이름·이메일·비밀번호·브라우저 지문을 수집하지 않고 visitor_id를 타인 화면에 표시하지 않는다.
- 기기·브라우저 변경·쿠키 삭제·시크릿 모드는 새 visitor가 될 수 있다. 고유 visitor는 실제 사람 수가 아니며 한 사람의 중복 참여를 완전히 방지하지 못한다.
- 쿠키 차단으로 visitor_id를 정상 유지할 수 없으면 실험 참여 불가 안내를 표시한다. 임시 ID를 매 요청 발급하여 참여를 허용하지 않는다. 쿠키 유지 확인 전에는 실험 방문·참여 이벤트를 수집하지 않아 식별 실패 요청이 표본을 늘리지 않게 한다.

### 7.2 관리자 인증

- 별도 계정 시스템을 만들지 않는다. 환경변수의 관리자 인증 정보로 **HTTPS HTTP Basic 인증**을 사용한다.
- 관리자 페이지와 모든 CSV 경로에 동일하게 적용한다. 실패 시 데이터·파일을 제공하지 않는다.
- 비밀값은 코드·저장소·브라우저 스크립트·URL에 넣지 않는다. 인증 설정 누락을 무인증 공개로 대체하지 않는다.

### 7.3 테스트 visitor 제외

- 개발 테스트 visitor는 서버의 is_test 표시와 exclusion_reason으로 식별한다. 테스트 요청은 저장하되 모든 실험 지표·50명 표본·성공 판정에서 제외한다. Production 신규 visitor는 항상 is_test=0이며 admin_test cookie를 사용하지 않는다. 관리자 로그인은 기존 visitor의 전체 이력을 재분류하지 않는다. LOCAL_DEVELOPMENT의 수동 방문자 격리는 유지한다.
- 테스트 시작 전에 해당 ID를 지정한다. 사후 테스트 식별 시에도 그 visitor의 범위 내 모든 이력을 동일하게 제외한다. 클라이언트가 임의로 테스트 여부를 지정해 집계를 바꾸지 못하게 한다.
- 실제 사용자에게 보이는 반응 분포·감상·좋아요·답글 및 그 수에서도 테스트 데이터를 제외하여 실험 UX에 영향을 주지 않는다.
- 관리자 원천 확인·CSV에는 테스트 여부와 제외 사유를 포함하며 일반 실험 집계와 구분한다. 별도 테스트 사용자 관리 UI는 추가하지 않는다.
- 관리자 화면은 전체 KPI와 책별 compact card를 기본으로 제공한다. 상세 지표는 접어서 보존하며 테스트 visitor 전용 집계 UI는 제공하지 않는다. 기존 분모·최초 성공·선후 관계·CSV 정의를 유지한다.

## 8. 데이터 모델

### Seed onboarding과 cohort

- 관리자 서버/DB 권한으로 `create-seed-links` CLI를 실행해 1–100개의 일회용 URL을 필요할 때 생성한다. Production/remote에는 명시적 확인이 필요하고 자동 생성하지 않는다. [운영 절차](seed-onboarding.md)를 따른다.
- 256-bit 난수 token의 SHA-256 hash와 생성·만료·소비 시각을 `seed_invites`에 저장한다. 원문 token과 credential은 저장/CSV 출력하지 않는다. 기본 72시간 만료이며 생성 시 visitor/event는 만들지 않는다.
- 첫 GET은 미리보기 안전 확인 화면만 제공하고, 브라우저 nonce와 서명 form을 검증한 POST에서 한 transaction으로 소비·visitor 생성·`seed_participants` 연결을 수행한다. 기존 visitor cookie가 있는 브라우저는 거부한다.
- `seed_participants(visitor_id PK/FK, created_at)`는 visitor의 영구 seed 상태다. 기존 visitors 테이블·is_test 정책을 유지하고 additive init-db로 등록한다.
- Normal은 공개/KPI/emoji·poll 분포에 포함한다. Seed는 감상을 공개하지만 모든 실험 KPI·emoji/poll 분포·작성자 CSV 행에서 제외한다. Test는 기존과 같이 KPI와 production 공개에서 제외하며 로컬 격리와 원천 CSV 정책을 유지한다.
- Normal이 seed 감상을 실제로 보고 남긴 others_reveal·like·reply는 normal 작성자의 행동으로 정상 집계한다. Seed 감상에 별도 표시를 붙이지 않고 기존 지표 정의와 노출 검증을 유지한다.

현재 상태는 분포·목록·현재 수의 기준, 이벤트는 성공 참여·공개·시도·시간 순서의 기준이다. 둘을 혼동하지 않는다.

| visitor_id, event_type, timestamp | 모두 필수. 확인된 익명 ID·허용 이름·서버 UTC 시각 |
| page_view_id | 모두 필수. 랜딩/도서 문서 로드마다 새 UUID |
| book_id | 도서 행동 필수. landing_view만 NULL 허용, 가짜 도서 ID 금지 |
| content_version_id | 도서 페이지 행동 필수. landing_view/book_select는 NULL 가능 |
| landing_page_view_id, display_position | book_select 필수. 실제 랜딩과 1~3 위치 |
| displayed_book_order | landing_view 필수. 실제 세 도서 순서 |
| source_book_select_event_id | 선택에서 진입한 book_view의 연결. 직접 방문은 NULL |
| target_type, target_id | 대상 행동 필수. 반응·감상·답글 ID |
| option_id, previous_option_id | 선택·변경·취소 시 전후 선택 식별 |
| action | emoji_reaction/poll_vote는 select/change, short_review_update/full_review_update는 edit/restore 필수. 취소는 별도 이벤트, 재작성은 최초 submit 아님 |
| reveal_source | short_reviews_reveal/others_reveal 필수. short_review_submit / community_open / community_restore / return_visit |
| exposure_area | others_reveal 필수. individual_short_reviews 또는 community_reviews. 실제 타인 감상 영역 식별 |
| cause_event_id | 공개 원인이 존재하면 연결. 선택·제출·커뮤니티 이벤트 |
| exposure_context | 참여·상호작용 필수. 영역별 선행 노출·공개 참조 |
| client_occurred_at, client_sequence | 브라우저 관측 필수. 발생 시각·페이지 순서, 서버 집계 시각 대체 불가 |

단일 results_exposed_before_action은 폐기한다. exposure_context는 같은 도서의 emoji_results_reveal, poll_results_reveal, short_reviews_reveal, community_open, others_reveal 선행 참조를 각각 구분한다. 현재 페이지·이전 방문 노출을 구분하며 수집 누락으로 모르는 상태를 미노출이라고 단정하지 않는다.

로그에 본문을 중복 저장하지 않고 ID와 필요 시 본문 길이를 연결한다. 본문 수정·삭제 후에도 종류·사용자·도서·시각·대상은 추적 가능해야 한다.

### 8.3 무결성

- 외래키 활성화, 유효 도서·선택지·게시물 및 대상 도서 일치 검증.
- reviews.review_type은 short/full로 제한한다. 각 본문 길이·공백 제한과 논리 삭제 여부를 저장·조회에서 검증한다.
- 저장·변경·취소·수정·삭제와 대응 성공 이벤트는 같은 트랜잭션. 한쪽만 남지 않는다.
- 요청 중복 방지를 실제 데이터 생성에도 적용한다. event_id·반응·글·좋아요 유일 제약으로 다중 탭을 처리한다.
- 이벤트 이름·시각·도서·visitor 및 대상 조회 인덱스를 둔다.
- 원천 이벤트를 수정·삭제로 덮어쓰지 않는다. 테스트 제외는 ID·사유 등 재현 가능한 표시로 처리한다.

## 9. 이벤트 로깅과 발생 조건

### 9.1 공통 원칙

- 아래 이벤트를 서버 SQLite에 기록한다. 콘솔·메모리 기록만으로 완료하지 않는다.
- 노출·시작·CTA 공개는 브라우저 관측, 저장 성공은 서버 처리에서 생성한다. 서버는 맥락·상태·대상을 검증한다.
- 검증·DB 실패·중단 요청은 성공 이벤트가 아니다. 저장된 반응의 사용자 취소는 별도 성공 상태 변경이다.
- 응답 확인 전 수집 완료로 간주하지 않는다. 재시도는 같은 event_id다.
- 비동기 도착 순서만으로 노출 전후를 단정하지 않고 페이지 순서·원인 참조로 분석한다. 누락·불일치는 진단한다.
- UTC 저장과 관리자 표시 시간대·기간을 명시한다.

| 이벤트 | 발생 조건 | 단위·중복 기준 |

### 9.3 공개·노출 이벤트

| 이벤트 | 발생 조건 | 단위·의미 |
| --- | --- | --- |
| emoji_results_reveal | 공개 가능한 이모지 결과 50% 이상 실제 viewport 진입 | page_view_id당 최초 1회, 변경마다 재생성 안 함 |
| poll_results_reveal | 공개 가능한 투표 결과 50% 이상 실제 viewport 진입 | page_view_id당 최초 1회 |
| short_reviews_reveal | 공개된 타인 한 줄 영역 50% 이상 실제 viewport 진입 | page_view_id+reveal_source당 최초 1회, 두 경로 구분 |
| community_open | 사용자 CTA 선택으로 커뮤니티 실제 공개 | page_view_id당 최초 1회, 노출·실패·자동 복원 제외 |
| others_reveal | 진입 경로와 무관하게 실제 타인 감상 영역 50% 이상 viewport 진입 | page_view_id당 최초 1회. 직접 공개·자동 복원·개별 한 줄 공개 경로 식별 |

community_open은 사용자가 CTA를 직접 선택하여 커뮤니티를 연 의도 행동이다. others_reveal은 경로와 무관하게 실제 타인 감상을 볼 수 있는 위치까지 도달한 노출 행동이다. 두 이벤트를 합치지 않는다. 이모지·투표 분포는 타인 감상이 아니며 others_reveal을 만들지 않는다.

최초 CTA 선택·실제 공개 시 community_open, 실제 타인 감상 50% 노출 시 others_reveal이다. 재방문 자동 복원에는 community_open이 없고, 복원된 감상 영역이 50% 노출되면 해당 페이지의 others_reveal이 발생한다. 직접 공개했으나 노출하지 않은 경우도 구분한다.

- 노출은 활성 탭에서 영역의 50%가 실제 viewport에 들어온 최초 시점이다. 추가 체류시간 조건은 없다. DOM 생성·서버 응답만으로 기록하지 않는다.
- 50%는 관측 대상으로 확정한 실제 발췌·결과 영역의 면적 기준이다. 화면보다 지나치게 큰 영역은 이 조건을 충족하지 못할 수 있다. 제목이나 임의의 작은 표식을 전체 결과 노출 대신 사용하지 않는다. 전체 조회 정책을 유지하면서 각 실제 영역의 관측 범위·레이아웃 크기는 17절에서 확정한다.
- 한 줄 제출로 개별 영역이 열리면 reveal_source=short_review_submit, 커뮤니티에서 열리면 community_open이다. 재방문 시 기존 제출 자격의 개별 공개는 return_visit이며 최초 원인을 연결한다.
- 커뮤니티 자동 복원 경로의 실제 노출은 reveal_source=community_restore로 기록하며 과거 직접 community_open을 원인으로 연결한다. 새 community_open을 만들지 않는다.
- 커뮤니티 경로는 진입 당시 한 줄 최초 제출 이력 유무를 함께 연결한다. 따라서 미작성자의 커뮤니티 공개와 이미 작성한 사용자의 커뮤니티 공개를 구분할 수 있다.
- 같은 페이지에서 두 경로가 실제 노출되면 각각 기록 가능하되 고유 열람자는 중복 제거한다.
- 같은 로드에서 개별 한 줄과 커뮤니티 모두 실제 노출되어도 others_reveal은 최초 1회다. 최초 경로는 exposure_area/reveal_source로, 한 줄 상세 경로는 short_reviews_reveal로 구분한다. 자신의 글만 있거나 실제 노출이 없는 DOM·서버 응답만으로 기록하지 않는다.

### 9.4 노출 전후 분석

- 각 결과 최초 노출, 한 줄 공개 경로, 직접 커뮤니티 열기, 감상 노출 이후 상호작용을 구분한다.
- 이모지 분포만 본 사용자는 타인 감상 열람자가 아니다. 커뮤니티 열기와 감상 실제 노출도 구분한다.
- 참여 이벤트의 영역별 exposure_context와 과거 참조를 사용한다. 첫 반응 분석에서는 어떤 타인 정보가 선행했는지 확인한다.
- 주 참여율은 노출 전후를 모두 포함한 성공 참여 이력이다. 세 반응을 필수 순차 퍼널로 해석하지 않는다.

## 10. 중복·새로고침·삭제 처리

| 상황 | 저장 | 고유 집계 |
| --- | --- | --- |
| 랜딩·도서 새로고침 | 새 page_view_id의 방문·실제 재노출 가능 | 같은 visitor 한 번 |
| 같은 event_id 재전송 | 기존 처리 결과 반환 | 추가 없음 |
| 같은 event_id에 다른 내용 | 충돌 거부, 원천 보존 | 추가 없음 |

| 수정·삭제 | 별도 이력, 최초 submit 유지 | 참여 사실 유지 |
| 삭제 후 감상 재작성 | 같은 review_id 재활성화, update(action=restore), 새 submit 없음 | 최초 참여자 그대로 |
| 결과 공개 후 취소·한 줄 삭제 | 현재 상태만 변경, 공개 자격 유지 | 과거 참여자 그대로 |
| 재방문 커뮤니티 자동 복원 | 새 community_open 없음, 실제 노출 시 새 페이지 others_reveal | 직접 진입자·노출자 각각 중복 제거 |
| 삭제 본문 폐기 | 종료 후 본문만 제거·폐기 시각 보관, 새 참여 이벤트 없음 | 과거 참여·상호작용 유지 |
| 여러 답글·좋아요 | 새 답글·대상별 기록 | 행동 참여자 한 번 |
| 입력창 반복 활성화 | 동일 로드 start 중복 제외 | 시작자 한 번 |
| 응답 유실·DB 실패 | 동일 ID 재시도, 데이터·이벤트 함께 커밋/롤백 | 실패는 참여 아님 |
| 여러 도서 참여 | 도서별 기록 | 전체 합집합 한 번 |

start만 남은 이탈은 정상 관측값이다. 같은 본문이라는 이유만으로 의도적인 새 답글을 재시도로 판단하지 않는다. 식별자 삭제로 새 ID가 생기는 한계는 명시한다.

삭제 감상에 연결된 좋아요·답글은 화면에서 숨기되 과거 상호작용 이력은 보존한다. 현재 유효 수와 기간 중 행동 사용자 수를 혼동하지 않는다.

## 11. 지표 계산

### 11.1 공통 집합

- 확정 기간은 시작 포함·종료 미포함이다. 콘텐츠 범위·제외 정책·시간대를 명시한다.
- 모든 아래 집합에서 is_test로 표시된 개발 테스트 visitor를 제외한다. 관리자 판정·표본·도서별/전체·랜딩·선택·노출·상호작용에 동일하게 적용한다.
- V_b: 기간 내 해당 도서 book_view 사용자, V: 모든 V_b 합집합.
- U_b(e): 기간·도서의 이벤트 e 사용자 중 V_b에 속한 집합. U(e): 모든 U_b(e) 합집합.
- C_b: U_b(community_open), C: 전체 합집합. 실제 직접 커뮤니티 공개 사용자다.
- E_b: U_b(others_reveal), E: 전체 합집합. 경로와 관계없이 실제 타인 감상 노출 사용자다.
- L_b/R_b: E_b 사용자 중 같은 visitor_id·book_id의 others_reveal 이후 각각 like/reply_submit 성공이 있는 집합. 전체 L/R은 도서별 해당 집합의 합집합이다. community_open 유무·새 발생 여부는 조건이 아니다.
- 선행 노출과 상호작용은 집계 기간 내 이벤트로 순서를 확인한다. 같은 페이지는 관측 순서·참조, 다른 페이지는 확인 가능한 시각·이력으로 연결한다. 순서를 확인할 수 없는 누락은 진단하며 노출 이후라고 임의 추정하지 않는다.
- 도서별 수를 더해 전체 고유 수를 만들지 않는다. 다른 도서의 선행 행동은 현재 도서의 조건을 대신하지 않는다.
- 기간 밖 행동은 주 지표에 섞지 않는다. 당시 작성 여부 판정에 필요한 과거 최초 제출 이력은 참조하며 CSV에서도 기간 외 자료로 구분한다.
- 모든 비율은 분자 집합 크기 / 분모 집합 크기 × 100이다. 0 분모는 N/A, 판정은 원 비율이다.

### 11.3 랜딩·선택

- 랜딩 고유 방문자는 landing_view의 서로 다른 visitor_id다. V와 별도 표시한다.
- 도서 선택 횟수·고유 선택자는 book_select 기준이며 도서 방문을 대신하지 않는다.
- 도서·display_position별 선택 횟수·고유 수를 분석한다. 위치별 실제 노출 분모는 landing_view 순서로 재현한다.
- 선택 후 book_view 도달은 source_book_select_event_id로 확인한다. 직접 진입은 따로 구분한다.

### 11.4 커뮤니티·상호작용

| 지표 | 분자 또는 집합 | 분모 |
| --- | --- | --- |
| 커뮤니티 직접 진입자 수·직접 진입률 | C | V |
| 타인 감상 실제 노출자 수·노출률 | E | V |
| 타인 감상 노출 후 좋아요 참여율 | L | E |
| 타인 감상 노출 후 답글 참여율 | R | E |
| 상호작용률 | L ∪ R | E |
| 타인 감상 노출 후 상호작용 사용자 수 | L ∪ R | 없음 |
| 한 줄 미작성 상태 커뮤니티 직접 진입자 수 | 첫 community_open 이전 같은 도서 최초 short_review_submit 이력이 없는 C 사용자 | 없음 |
| 한 줄 작성 후 커뮤니티 직접 진입자 수 | 첫 community_open 이전 같은 도서 최초 제출 이력이 있는 C 사용자 | 없음 |
| 한 줄 미작성 상태 타인 감상 실제 노출자 수 | 첫 others_reveal 이전 같은 도서 최초 한 줄 제출 이력이 없는 E 사용자 | 없음 |
| 한 줄 미작성 상태 감상 노출 후 좋아요/답글 사용자 수 | L ∪ R 중 상호작용 당시 같은 도서 최초 한 줄 제출 이력이 없는 사용자 | 없음 |
| 자유 감상 작성률 | U(full_review_submit) | V |

상호작용률 분모는 실제 타인 감상 노출자 E다. 직접 진입자 C·도서 방문자 V를 대신 사용하지 않는다. 분자는 같은 도서에서 해당 사용자의 others_reveal 뒤 성공한 좋아요 또는 답글 제출의 합집합이다. 이모지·투표 결과만 본 사용자는 E가 아니다.

자동 복원에서 community_open이 새로 발생하지 않아도 실제 others_reveal 이후 상호작용은 포함한다. 이전 페이지 노출 뒤 재방문 상호작용도 같은 도서의 기간 내 선후 관계가 확인되면 포함한다. 분자가 E의 부분집합이 되도록 먼저 도서별 조건을 검사한 뒤 전체 visitor 합집합을 만든다.

‘미작성’은 기본적으로 행동 당시 최초 제출 이력이 없다는 의미다. 나중에 작성·삭제해도 당시 분류를 소급 변경하지 않는다. 기간 끝까지 한 줄 제출이 없는 사용자 집합도 보조 분석으로 재현 가능하게 한다.

도서별 첫 직접 진입의 작성/미작성은 상호 배타적이며 첫 실제 노출의 상태도 별도로 판정한다. 전체는 도서별 판정 후 visitor 합집합이다. 여러 도서에서 상태가 다른 사람은 두 전체 집합 모두에 속할 수 있으므로 두 수를 더해 C 또는 E를 계산하지 않는다.

### 11.5 횟수·고유 수·현재 상태 구분

- 이벤트 횟수: 중복 재시도 제거 후 실제 이벤트 행 수.
- 고유 참여자: 해당 행동의 서로 다른 visitor_id 수.
- 현재 반응·글·좋아요·답글 수: 취소·삭제되지 않은 유효 상태 수.
- 최초 성공 참여: 현재 상태와 무관한 최초 성공 사실.

예: 방문자 10명, 이모지 4명, 투표 3명, 중복 2명이면 가벼운 참여자는 5명·50%다. 새로고침 5회는 방문자 수를 늘리지 않는다. 한 사람이 세 글에 좋아요를 하면 이벤트 3건·참여자 1명이다. 한 줄 삭제 후에도 최초 제출자 1명은 유지한다.

작성 완료율, 이모지→한 줄·투표→한 줄·한 줄→자유 전환은 같은 도서의 시간 순서·최초 성공을 확인하는 탐색 분석이다. start 누락·참조 불일치·노출 누락은 원천을 지우지 않고 품질 확인 대상으로 표시한다.

## 12. 관리자 결과 페이지

- 인증된 관리자 경로에서 전체·도서별 모든 필수 지표를 제공한다.
- 전체 50명 조건, 30%·10% 각각과 동시 충족, 데이터 품질 상태, 검증/기각/판정 불가를 바로 확인한다.
- 랜딩·선택과 book_view 분모를 분리하고 개별 결과·커뮤니티·감상 노출 지표도 구분한다.
- 직접 진입률 C/V, 실제 노출률 E/V, 좋아요율 L/E, 답글률 R/E, 상호작용률 (L∪R)/E를 명시한다. 자동 복원 노출·상호작용도 포함하며 직접 CTA 지표와 합치지 않는다.
- 이벤트별 이벤트 수·고유 수를 별도 열로 표시하고 현재 유효 수와 과거 참여자 수를 혼동하지 않는다.
- 기간·시간대·도서·콘텐츠 버전·제외 기준·집계 시각·분모를 표시한다.
- 품질 확인 항목과 CSV를 제공한다. 실제 SQLite DB에서 집계한다.
- 관리자 화면 방문은 book_view가 아니다. is_test로 표시된 개발 테스트 visitor의 모든 행동을 실험 지표·표본에서 제외하고 제외 건·사유는 별도 원천 확인에 표시한다. 관리자 인증은 visitor의 is_test 상태를 변경하지 않는다.
- 50명 도달 상태와 운영자가 기록한 종료 상태·시각을 구분한다. 50명 도달로 자동 종료하지 않는다.
- 차트·실시간 갱신·CMS·계정 관리·별도 분석 서비스는 필수가 아니다.

- 테스트·오염 제외 표시는 사유와 함께 내보낸다. 필요한 과거 연결 이력은 기간 외임을 구분한다.
- 요약 지표에는 테스트 visitor를 포함하지 않는다. 원천은 테스트 표시를 보존하여 제외를 재현한다. C/V와 E/V 및 (L∪R)/E를 별도 metric_name·분자·분모로 Export한다.
- 본문 폐기 후에는 해당 본문을 빈 값으로 제공하고 body_purged_at으로 빈 글·삭제·폐기를 구분한다. 최초 제출 및 상호작용 지표는 본문 폐기 이후에도 동일하게 재계산 가능해야 한다.
- 여러 파일은 동일 읽기 스냅샷으로 일관되게 내보낸다.
- UTF-8·헤더·명시적 UTC, 쉼표·따옴표·줄바꿈·이모지 보존을 요구한다.
- 사용자 글의 스프레드시트 수식 실행을 막고 원문 복원 방법을 명시한다.
- 모든 다운로드에 관리자 인증을 적용한다. DB 경로·비밀값은 내보내지 않는다.

## 14. 비기능 요구사항

### 14.1 기술·배포

- Python 3, Flask, SQLite, HTML, CSS, Vanilla JavaScript. 프론트엔드 프레임워크 없음.
- 소규모 모델·집계에 맞춰 표준 sqlite3와 매개변수 SQL을 사용하고 ORM은 도입하지 않는 방향을 제안한다.
- 운영은 적합한 WSGI 서버·HTTPS다. Flask 개발 서버로 운영하지 않는다.
- DB는 영속 저장 위치에 두고 재시작·재배포 후 유지한다. 여러 독립 DB로 분산하지 않는다.
- 환경 설정·DB 경로·비밀값을 분리하고 설치·초기화·콘텐츠 등록·실행·백업/복구 절차를 문서화한다.

### 14.2 UI·접근성

- PC·모바일 반응형이며 같은 콘텐츠·기능·공개 조건을 제공한다.
- 가로 넘침 없이 읽기·입력·선택 가능, 키보드 조작·레이블·이모지 뜻 텍스트를 제공한다.
- 화면 크기로 실험 질문·정책을 바꾸지 않고 랜딩 배정 순서를 유지한다.
- 완주 유도·보상·불필요한 참여 단계를 넣지 않는다.

### 14.3 신뢰성·보안

- 외래키·유일 제약·트랜잭션·재시도 방지, 동시 잠금 실패 처리를 적용한다.
- SQL 바인딩·출력 이스케이프·서버 검증·쓰기 요청 보호를 적용한다. 사용자 글을 HTML로 실행하지 않는다.
- 공개 조건·소유자·도서·대상 관계를 서버에서 검사한다.
- DB 파일·관리자 데이터·CSV 공개 접근을 차단한다.
- 불필요한 개인정보·본문·비밀값을 운영 로그에 남기지 않는다.
- 백업/복구 후 최초 참여·변경·삭제·재활성화·공개 자격·테스트 제외·이벤트 연결을 유지한다. 본문 폐기 정책을 적용한 뒤 복구하더라도 폐기 대상 본문이 무의식적으로 다시 보관되지 않도록 사본 정책을 함께 적용한다.
- 브라우저 종료·단절의 노출 누락을 성공 저장과 구분하고 없는 노출을 자동 생성하지 않는다.

## 17. 남은 결정 필요 사항

랜딩·순서, 글 길이·개수, placeholder, 최신순 전체 조회, 50% 노출, 쿠키 30일, 관리자 최소 인증, 표본 50명은 확정이다. 이번에 취소 후 결과 유지, 삭제 후 같은 글 재활성화, 한 줄 삭제 후 공개 유지, 커뮤니티 자동 복원, `내 감상` 표시, 답글 오래된 순, 운영자 직접 종료, 테스트 visitor 제외, 논리 삭제·종료 후 본문 폐기 가능, 쿠키 차단 시 참여 불가도 확정됐다. 아래에는 실제로 남은 세부 결정만 기재한다.

## 18. 완료 조건 — Acceptance Criteria

### 18.1 플로우·공개

- [ ] `/`의 세 도서 랜덤 순서·가능한 재방문 유지와 실제 순서/위치 로그를 확인할 수 있다.
- [ ] 한 권만 종료 가능, 완주 유도·별도 완료 버튼 없음, 세 반응 미참여 커뮤니티 진입 가능하다.
- [ ] 상황 설명·확정 실제 원문 텍스트를 제공하고 이미지·요약만으로 대체하지 않는다.
- [ ] 이모지 성공은 이모지만, 투표 성공은 투표만 공개한다. 다른 도서·종류 결과는 공개하지 않는다.
- [ ] 한 줄 제출·미제출 커뮤니티 두 공개 경로를 구분한다.
- [ ] 커뮤니티는 감상·좋아요 수·답글/수를 제공하지만 미참여 반응 결과는 계속 숨긴다.
- [ ] 반응 취소·한 줄 삭제 후에도 이미 획득한 공개 자격을 유지하고 재방문에 복원한다.
- [ ] 같은 visitor·도서의 이전 직접 공개 이력으로 커뮤니티를 자동 복원하되 community_open을 추가하지 않는다.
- [ ] 최신순 전체 조회이며 페이지네이션·무한 스크롤·인기순은 없다.
- [ ] 자신의 글은 같은 목록에 `내 감상`으로 표시하고 답글은 오래된 순이다.

### 18.2 글·반응

- [ ] 이모지·투표 현재 각 1개, 변경·취소 가능, 동일 요청 중복 참여 없음.
- [ ] 한 줄 150자·자유 2,000자, 종류별 1개, 수정·삭제 가능, 공백만 불가, 최소 분량 없음.
- [ ] 답글 300자·여러 개·수정·삭제 가능, 중첩 없음.
- [ ] 좋아요 취소 가능, 동일 visitor·감상 현재 1개.
- [ ] 감상 미작성자도 타인 자유·한 줄 조회와 좋아요·답글 가능하다.
- [ ] 소유자 검증, 본인 글 상호작용 제외, 삭제·취소 후 성공 참여 사실 보존.
